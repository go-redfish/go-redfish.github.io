The client

A BMC, read safely.

github.com/go-redfish/redfish finds the service root, authenticates, and reads. It was written for the go-llmflow gateway, which bills the electricity a shared GPU machine uses, and serves any tool that needs a BMC's answers.

🔎

Service discovery

It starts at /redfish/v1 and follows the links the service gives, rather than assuming a vendor's paths.

🔑

Basic or session

HTTP Basic over https, or a session whose token is used and then logged out. A CA file can be given for a BMC's own certificate.

⚡

From reads to energy

A Meter turns successive reads into energy: the difference of a counter, or the trapezoid of a polled power, with no interpolation across a gap and no negative energy when a counter resets.

Security

A BMC's answer is untrusted input.

A BMC is a privileged, often old, network service. The client treats everything it says as data to be checked.

🔒

https only

A URL that is not https, or that carries credentials, is refused. Certificates are verified, TLS 1.2 or later, and there is no switch to turn verification off.

📏

Bounded answers

A response is read up to a fixed size; a malformed or oversized one is a typed error.

🧪

Fuzzed

The JSON decoders and the meter are fuzzed, with the corpus committed, and CI runs go vet, go test -race and govulncheck.
